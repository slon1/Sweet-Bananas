# Протокол работы Cursor

## Роли
Архитектор ставит ADR и ТЗ, принимает рапорты. Cursor реализует и сам архитектуру не меняет. Оператор передаёт сообщения. При неясности, неполноте или противоречии — остановиться и задать вопрос, не решать молча.

## Обязательные правила
- Unity 6000.5, C#, DOTween, Extenject 9.2, UniTask 2.5.11 (`UNITASK_DOTWEEN_SUPPORT`).
- **Без asmdef.**
- UI на Unity UI (`Image`, TextMeshPro); `SpriteRenderer` только для физических объектов.
- Canvas: ScreenSpace-Camera; CanvasScaler 1080×2160, портрет. Match — по ADR-001 (D3).
- Новый код: `UniTask`, без `async void` и `Task`.
- Спрайты брать по `DOC/screens.md`. Сцену `Loader` и ее скрипт не менять.
- Нет «сделал заодно»: только то, что в ТЗ.

## Цикл задачи
1. Прочитать ТЗ и ADR; противоречия — вопросом.
2. `git status`, работать в одном логическом коммите на задачу.
3. Реализовать. Проверить: компиляция, чистая консоль, запуск сцены.
4. Закоммитить и запушить, хеш — в рапорт.
5. Рапорт (файл `DOC/reports/REPORT-NNN.md` или текст): сделано по пунктам ТЗ; изменённые файлы; отклонения и причины; результаты проверок; открытые вопросы.

## Синхронизация
Архитектор перед разбором рапорта сверяет хеш коммита с git. Если не совпадает — разбор останавливается до синхронизации.
