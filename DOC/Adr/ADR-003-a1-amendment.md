# ADR-003-a1: поправка к ADR-003 (spike физики)

Статус: принято (архитектор). Дополняет и частично заменяет ADR-003. Основание: ревью 2a, `Physics2DSettings.asset`, размеры `candyNN`.

## A1. Потолок угловой скорости
В `ProjectSettings/Physics2DSettings.asset` стоит `m_MaxRotationSpeed: 360`. Он может обрезать тап (`TapSpeed` 600°/с) и вращение ленты-комка.
- В `GameConfig` добавить `MaxRotationSpeed`; `GameBootstrap` применяет его через `Physics2D.maxRotationSpeed`. `ProjectSettings` не менять.
- Единицы и стартовое значение определить по документации Unity 6000.5 и замером (в градусах/с или радианах/шаг). Если API отсутствует или помечен obsolete — остановиться и описать в рапорте, ничего не придумывать.
- Критерий: `MoveRotation` на 600°/с даёт измеренную `angularVelocity` кинематического тела не ниже 570°/с. Тело ленты в комке не должно упираться в потолок: замерить максимум `angularVelocity` сегмента за серию бросков.
- Попутно записать в рапорт эффективные `Physics2D.bounceThreshold` / velocity threshold (в Physics2DSettings `m_VelocityThreshold: 1`): они влияют на отскок (D24 п. 4, 5).

## A2. Толщина ленты (правка D21)
`candyNN` имеют размер около 355×119 px (3.55×1.19 юн.). Физическая толщина из высоты спрайта даёт неработающую цепь (сегмент при 8 штуках имеет длину около 0.44).
- `GameConfig.RibbonColliderThickness`, старт **0.3**, обязательно ≤ длины сегмента. Это толщина `CapsuleCollider2D` (горизонтальной, `size = (длина сегмента, толщина)`).
- Визуал независим от физики. Меш берёт толщину и UV-диапазон по прямоугольнику непрозрачных пикселей `candyNN` (порог альфы > 0), а не по рамке текстуры. Замер — скриптом по PNG без Read/Write (как для `bg.png`); результат (bbox в пикселях, юниты) в рапорт, значения в сериализованные поля `RibbonMesh`.
- Полная длина ленты = ширина непрозрачной части в юнитах. Визуальный центр ленты на оси цепи.
- Добавить `GameConfig.RibbonSpawnFraction` (старт 0.25): доля длины палочки от оси до центра ленты в момент спавна (D21: ≈ 25 %).

## A3. Спрайт `pointerN`
Использовать весь спрайт 730×730 (D15). Проверить в коде/рантайме, что `sprite.rect` = 730×730 (имя в мете `pointerN_0` допустимо). Записать в рапорт. Ориентация: головка слева, палочка вправо при угле 0; если PNG нарисован иначе — повернуть дочерний объект со спрайтом, а не сам `Rigidbody2D`.

## A4. Канонические имена
Поле предела суставов — `JointLimitDeg` (D23), а не `JointLimit` из D21.

## A5. Бонус «с первого раза» (правка D18)
В D18 фраза «счёт бросков» заменяется на `FailCount` по GDD §3: бонус теряется после любого проигрыша на уровне. `LevelRules` хранит `FailCount` (сброс при загрузке уровня) и `IsFirstAttempt => FailCount == 0`. Счёта бросков нет.

## A6. Определения измерений D24 (обязательные)
Точки измерения, чтобы результаты были сопоставимы:
- **п. 2 (туннелирование):** в системе координат палочки (x вдоль, y перпендикулярно, 0 = ось) центр любого сегмента при x в [0, длина палочки] не должен иметь y < 0 после первого контакта с палочкой. Проверять каждый FixedUpdate.
- **п. 3 (рычаг):** одинаковый тап, лента спавнится у основания и у кончика. Дальность = горизонтальное расстояние от оси леденца до центра ленты в момент, когда центр ленты при падении пересекает уровень `pivot.y`. Разница ≥ 2 юн.
- **п. 4 (ловля):** лента падает с высоты 3 юн над удерживаемой палочкой (0°). Отсчёт 0.3 с от первого контакта. Вертикальная скорость центра ниже 0.5 юн/с, максимальный подъём центра после первого контакта ≤ 0.2 юн.
- **п. 5 (посадка на цель, 002-B):** максимальный подъём центра ленты над точкой первого контакта ≤ 0.3 юн.
- **п. 7:** средний шаг физики из Profiler (editor) ≤ 1 мс; аллокации меша по кадрам — 0 (GC Alloc в `RibbonMesh` по профайлеру).
