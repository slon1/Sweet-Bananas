# ADR-003-a5: закрытие spike ленты (поправка к ADR-003, a2, a4)

Статус: принято (архитектор, решение оператора). Приоритет над ADR-003, a1–a4 при противоречии.

## A21. Критерии закрытия D24.1 и D24.11
Основание: REPORT-002-A2 §9–10. Разрыв > 0.21 юн возникает только в фазе контакта с палочкой, короткий, не остаётся после остановки ленты и визуально незаметен (меш строится по серединам якорей, толщина 1.17 юн). Порог «0 разрывов» и бин 0.085 как критерии отменяются.

Серия 300 + 60, валидные броски:
1. NaN = 0; скорость сегмента ≤ 60 юн/с.
2. В фазе `stopped` зазор между якорями ≤ 0.05 юн на каждом шаге.
3. Бросков с первым зазором > 0.21 юн не более 2 % валидных.
4. `R_min ≥ 0.35` в каждом броске (без первых 0.1 с после спавна).
5. `spawn_invalid` ≤ 2 % (A20).

## A22. Параметры ленты (итог подбора)
- `JointLimitDeg = 25` (решение оператора по визуалу; `RestoreK`, толщина, `SegmentCount` и остальное остаются значениями 002-A).
- `(SegmentCount − 1) × JointLimitDeg = 175° ≤ 200°` (A12, кольцо невозможно).
- Привод палочки: `MoveRotation` (A9 закрыт, V1 не лучше).
- Коллайдер головки включён (A13).

## A23. Отменённое
E3–E7, остальная сетка E2s, расследование механизма разрывов (контакт со stick), расследование бросков 17 и 59, C7, верле (ADR-004 не нужен). Если критерии A21 не выполнены, решение принимает архитектор по данным разбивки, подбор «вслепую» не проводится.

## A24. Следующий шаг
002-B (цель, правила, Android-сборка). Замер FPS на Samsung S10 (D24.10) выполняет оператор по APK из 002-B. Параметры физики (`FixedDeltaTime` 1/120, итерации 24/12) считаются кандидатами на удешевление, если FPS < 55.
