## Ответы
1. **Стопы по п. 2.**
   - Гипотеза A29 не подтвердилась (п. 2.3, tip пуст на 0.25 при 0.10): стоп, п. 4–5 не выполнять, рапорт с дампом (Lollipop + диагностика).
   - Tip есть, но критерии D24.9 не сходятся (п. 2.4): не стоп. Взять **временное** значение `StickFriction`: ближайшее к критерию (время до кончика на доле 0.25 ближе к 3.2 с, при равенстве большее). Оно подставляется через `DebugSetStickFriction` в прогонах п. 4–5. В `GameConfig.asset` пишется только `TapSpeedDegPerSec`, `StickFriction` остаётся 0.4 до моего решения. В рапорте явно: «A29 подтверждена, D24.9 не сходится», таблица Rest Probe, временное значение.
   - Эти два случая различать в рапорте отдельными заголовками.
2. **Диагностика A29 (п. 2.3).** Снимается в фазе покоя Rest Probe (без нажатия), на t = 1 / 3 / 6 с от спавна, при `StickFriction` 0.10, доли 0.25 и 0.50. Контакты через `Physics2D.GetContacts` / `Collider2D.GetContacts` за шаг: `ContactPoint2D` уже содержит `normalImpulse`, `tangentImpulse`, `separation`. Временный probe-компонент не нужен.
3. **Метрика A30.** Да. На каждом шаге: хотя бы один сегмент `IsTouching(target)` и ни один сегмент `IsTouching(stick)` и `IsTouching(head)` — «чистый контакт». Шаги со смешанным контактом игнорировать до первого чистого, на нём зафиксировать Y центра. Подъём = максимум `Center.y` после него минус зафиксированное Y.
4. **Конфиг в п. 4.** Один клонированный `GameConfig` через `DebugSetConfigOverride`, меняется только `TapSpeedDegPerSec`. `StickFriction` применяется через `DebugSetStickFriction`: финальное из п. 2 или временное по п. 1.
5. **Критерий A32.** На каждое значение 55 бросков (всего 220). «≥ 10 %» = **≥ 6 побед** из 55; «слишком легко» = **≥ 23 побед** (> 40 %). Из значений, прошедших порог, всегда берётся наибольший `TapSpeed`.
6. **Подтверждение на 1×.** Равномерная выборка по индексам из списка побед выбранного `TapSpeed` (до 8 ячеек), как в 002-B. Побед меньше 8, берутся все.
7. **Разбивка разрывов (п. 5).** Колонки (фаза, скорость сегмента 7, касание цели) добавлять только в B2-раннер, production-код не трогать (кроме `Lollipop.cs` по п. 1 ТЗ).
8. **Подготовка.** Опираемся на дерево `548b682` (там уже есть доработки бенча: `_findStart`, порядок аргументов CSV, Level1/GameFlow). `ae063e5` только удалил бенч, ничего оттуда не переносить.
