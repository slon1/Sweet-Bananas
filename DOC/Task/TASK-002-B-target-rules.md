## 1. Цель (D18, D8)
`TargetHolder`: спрайт `game01` (Single, 741×648, PPU 100) на `SpriteRenderer`, `PolygonCollider2D` по физическому контуру спрайта (fallback-генерация включена, кастомного shape нет), `PhysicsMaterial2D` с `TargetFriction`, sorting layer `World`.
- Если контур даёт мелкие островки или шумный полигон — упростить кодом (удалить пути с площадью/числом точек ниже порога, упростить Дугласом–Пекером с допуском в юнитах) **без правки импорта**; описать в рапорте число путей и точек до и после.
- **Положение из Figma:** instance `1` в кадре `Game1` (`1225:85`) считать от рамки кадра, а не от общего холста (в `screens.md` X=982 при ширине 741 выходит за 1080 — координата общего холста). `world = (x/100, (2160 − y)/100)` для центра спрайта. Сверить по `preview/Game1-1.png`. Однозначно не получается — **остановиться и спросить**.

## 2. LevelRules (D22, A5)
- **Победа:** не менее двух сегментов `IsTouching` коллайдера цели, максимум скоростей сегментов ниже `SettleSpeedThreshold`, условие держится непрерывно `SettleSeconds`; иначе таймер сбрасывается. Затем `GameFlow.Win`, лента замирает.
- **Проигрыш:** центр ленты ниже `FailLineY = pivot.y − FailMarginUnits` либо за границей мира ±`FailMarginUnits` (в том числе сползла и упала, и соскользнула с цели и упала). Затем `GameFlow.Fail`, лента замирает, `FailCount++`.
- `FailCount` и `IsFirstAttempt` (A5). Счёта бросков нет.
- Перезапуск: кнопка `SpikeOverlay` (`Ribbon.ResetToSpawn()`, состояние `Playing`). Временный автосброс из 002-A удалить, его заменяет `LevelRules`. Попапы Win/PLAY AGAIN — этап 3.
- Состояния `GameFlow` менять только через `LevelRules`.

## 3. Приёмка (ADR-003-a1 A6)
Для пп. 5–7 — одноразовый editor-скрипт вне `Assets/Scripts`, удалить с `.meta` до коммита, упомянуть в рапорте; логика та же, что в рантайме.
1. **Посадка (п. 5):** отскок ленты после первого контакта с целью ≤ 0.3 юн (определение A6); число измерений и максимум.
2. **Проходимость уровня 1 (п. 6):** перебор: длительность нажатия 0.03…0.15 с с шагом 0.01 с × сдвиг старта 0…100 % длины палочки с шагом 10 % (143 сочетания). В рапорт: число побед, лучшие сочетания, ширина «окна побед» (смежные победные сочетания). Побед 0 — **стоп**; побед больше 40 % — отметить «слишком легко» (решение архитектору).
3. **Производительность (п. 7):** средний шаг физики с целью ≤ 1 мс (Profiler, editor), GC Alloc меша по кадрам = 0.
4. **Повторная проверка пп. 1–2 из 002-A** на 100 бросков с целью на сцене (NaN, разрывы, скорость).
Подбор `TargetFriction`, `RibbonFriction` и др. — в рамках D23; итоговая таблица в рапорт.
