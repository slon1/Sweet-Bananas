> **Модель для оператора: Grok.** Проектные решения: настройка цепи шарниров, подбор параметров по критериям. Запускать **после** TASK-002c (docs-чистка).

Основание: ADR-001 (D1, D2, D7), ADR-002, ADR-003 + **ADR-003-a1** (читать оба, при противоречии приоритет у a1), GDD v1.0. Цель, победа/проигрыш, HUD, магазин, попапы, `LevelData`, звук, прогрессия **не делаем**. `Loader` не трогаем, asmdef не создаём. Без `async void` и `Task`.

Эта часть проверяет главный риск проекта: цепь `Rigidbody2D` + `HingeJoint2D` (D2).

## 2. Объекты (ADR-003 D18–D21; в этой части: `Lollipop`, `ThrowController`, `Ribbon`, `RibbonMesh`, `SpikeOverlay`)
Привязки в `GameSceneInstaller`, объекты в `Scene.unity` под `WorldRoot`, sorting layer `World`.

**Лестница координат.** Положение и размер леденца `pointer1` взять из Figma (`get_metadata`, кадр `Game1`, слой `01`, а не общий холст; `world = (x/100, (2160 − y)/100)`, ADR-002 D11). В `screens.md` слой `01` описан как «цель / леденец» (905×905 при x=488, y=−80): если из метаданных и скриншота нельзя однозначно сказать, что это леденец и где центр его головки, — **остановиться и спросить**. Значения из Figma — только стартовые; ось вращения — центр головки.

**Lollipop (D19).**
- `Rigidbody2D` Kinematic, `Interpolate`, движение только `MoveRotation` в `FixedUpdate`. Спрайт `pointer1` целиком (A3) — дочерний объект, смещённый так, чтобы центр головки совпал с началом `Rigidbody2D`.
- Головка: `CircleCollider2D`, палочка: `CapsuleCollider2D`. `PhysicsMaterial2D` палочки (`StickFriction`) отдельный.
- Положительный угол = кончик вверх. Покой −25° (кончик вниз), тап до +35°, удержание 0°.

**ThrowController (D20).** Один указатель `<Pointer>/press` (Input System). Состояния: `Rest`, `Rise` (нажатие, подъём к 0° со скоростью `HoldRiseSpeed`), `Hold` (держим 0° до отпускания; наступает, если нажатие длится > `HoldThreshold`), `TapRush` (отпускание до порога: рывок к `TapPeakAngle` со скоростью `TapSpeed`), `Return` (возврат к покою `ReturnSpeed`). Новое нажатие прерывает `Return`. Состояние и целевой угол считаются в `FixedUpdate` (детерминизм); нажатия записываются флагами из callback. Нажатия поверх UI (кнопка оверлея) игнорировать (`EventSystem.current.IsPointerOverGameObject()`); если с touch не работает — описать в рапорте.

**Ribbon (D21 + A2).**
- `SegmentCount` сегментов: `Rigidbody2D` (`SegmentMass`, `Continuous`, `Interpolate`, линейное/угловое затухание из конфига) + горизонтальный `CapsuleCollider2D` толщины `RibbonColliderThickness`; `HingeJoint2D` между соседями с лимитами ±`JointLimitDeg`; все пары сегментов одной ленты игнорируют друг друга (`Physics2D.IgnoreCollision`).
- Возвращающий момент в `FixedUpdate`: для каждого сустава `τ = −RestoreK·угол − RestoreC·относительная угловая скорость`, приложить **парой** (+τ одному телу, −τ другому), чтобы не вносить момент в систему.
- Спавн/сброс `ResetToSpawn()`: лента прямая вдоль палочки, центр на расстоянии `RibbonSpawnFraction × длина палочки` от оси, скорости нулевые, угол палочки — покой. Метод публичный (понадобится `LevelRules` в 002-B). Для теста допускается задать долю спавна параметром (сдвиг старта).
- Оценка для старта `StickFriction`: Unity смешивает трение как √(f₁·f₂), при ленте 0.9 и палочке 0.2 даёт 0.42; при −25° скольжение идёт, если коэффициент ниже tan(25°) ≈ 0.466. Это оценка, подбор эмпирический по D24 п. 9.

**RibbonMesh (D1, A2).** Полоса из `SegmentCount + 1` сечений по якорям суставов (концы — по краям цепи), нормаль сечения — усреднённое направление соседних сегментов; толщина и UV-диапазон по bbox непрозрачной части `candy01` (A2). Пересчёт в `LateUpdate`, без аллокаций (предварительно выделенные массивы, `Mesh.SetVertices/SetUVs` по spans). Материал — спрайтовый unlit URP 2D, sorting layer `World`.

**SpikeOverlay** (`Game/Debug/`, только `#if UNITY_EDITOR || DEVELOPMENT_BUILD`; **на uGUI** в `HudRoot`, создаётся кодом, не IMGUI): средний FPS, время кадра, время шага физики, кнопка «Restart» (`Ribbon.ResetToSpawn()`). Временный автосброс при `центр ленты ниже pivot.y − FailMarginUnits` или за границей мира ±`FailMarginUnits`: в 002-B заменится на `LevelRules`.

## 3. Приёмка (ADR-003-a1 A6 — определения измерений)
Для пп. 1–4 — одноразовый editor-скрипт вне `Assets/Scripts` (например `Assets/_Task002ATemp/Editor`), удалить вместе с `.meta` до коммита, упомянуть в рапорте. Автоматика должна идти **по тому же коду**, что и рантайм (нельзя копировать логику ввода/ленты в скрипт); тестовые хуки допустимы только под `#if UNITY_EDITOR || DEVELOPMENT_BUILD`.
1. **Стабильность (D24 п. 1):** 300 бросков с разными длительностями нажатия и сдвигом старта — число NaN, разрывов цепи (> 0.2 × длины сегмента между якорями соседей), максимальная скорость сегмента (не выше 60 юн/с).
2. **Туннелирование (п. 2).**
3. **Рычаг (п. 3):** дальность у основания, у кончика, разница (≥ 2 юн).
4. **Ловля (п. 4):** вертикальная скорость через 0.3 с и подъём.
5. **Производительность (п. 7):** средний шаг физики (Profiler, editor), GC Alloc меша по кадрам.
6. **Стекание (п. 9):** время от спавна до кончика в покое (2.5–4 с), скорость сползания при 0° через 1 с (< 0.05 юн/с).
7. **A1:** измеренная `angularVelocity` кинематики при 600°/с и максимум угловой скорости сегментов; значения `Physics2D.maxRotationSpeed`, bounce threshold.
8. **A2/A3:** bbox `candy01`, выбранные толщина/длина; `pointer1` sprite.rect.
Результаты числами. Не выполняются пп. 1–2 после настройки ±×2 по итерациям и частоте — **стоп** и вопрос (запасной вариант D2 — отдельный ADR).
