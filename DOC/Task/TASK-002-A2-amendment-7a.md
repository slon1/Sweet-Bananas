# TASK-002-A2: поправка 7a (ответы на вопросы Cursor к поправке 7)

Всё, что не упомянуто, остаётся как в поправке 7. Решение: **берём в работу**, порядок G1 → G2 → короткий smoke → E0.

## Ответы
1. **G2, API.** Добавить `Ribbon.MaxHingeSlack()` (чистое чтение, без логов, `UNITY_EDITOR || DEVELOPMENT_BUILD`). `ValidateHingeAnchors()` оставить как есть: порог 0.001 и `LogError`, вызывается только из `Build` и `ResetToSpawn`. Бенч и Gap Sanity на шагах используют `MaxHingeSlack()`.
2. **G1, знак.** `Collider2D.Distance` < 0 при перекрытии, такой бросок автоматически `spawn_invalid=1`. Порог строго `< 0.01`.
3. **G1, 2 %.** Стоп, если `spawn_invalid_pct > 2.0`. На 120 бросках это 3 и более invalid. Значения 0–2 допустимы, но выводятся в `summary`.
4. **G3, гистограмма.** Каждый бросок попадает в один набор бинов 0.085 / 0.21 / 0.5 / 1.0 и в одну фазу (contact / flight / stopped): значение `max_gap` до первого шага с зазором > 0.21 и фаза, в которой этот максимум достигнут. Отдельно вывести список бросков с первым событием > 0.21: фаза, шаг, пара, значение. Валидные броски только.
5. **C7 / `RibbonMesh.cs`.** До E0 не делать. В белый список `RibbonMesh.cs` входит только для G4 после E0. В рапорте E0 записать «C7: отложено».
6. **B6 / B7.** До E0 не обязательны. Колонки B7 можно добавить, если это правка CSV на 5 минут; иначе «не сделано» в рапорте E0. `Run Rest Probe` — отдельным коммитом после отчёта E0, до E2.
7. **Отрицательный C0 clearance.** Формулировки из вопроса достаточно, отдельный прогон не нужен. Два дополнения:
   - в CSV каждого броска добавить `spawn_angle` (`lollipop.Angle` в момент замера) и `spawn_fixed_steps`;
   - в замере `spawn_clearance_step0` вызывать `Physics2D.SyncTransforms()` перед `Collider2D.Distance`. Гипотеза: после `SnapRest` поза коллайдера палочки не синхронизирована. Проверяется на данных E0 (если invalid исчезнут, гипотеза подтверждена; если нет — дамп из G1).
