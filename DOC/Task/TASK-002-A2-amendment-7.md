# TASK-002-A2: поправка 7 (E0 с контролями спавна)

> **Модель для оператора: Grok.** Приоритет над поправками 1–6 при расхождении. Основание: рапорт по `c5a8892`, ADR-003-a4.

Принято: F2.1–F2.2 поправки 6 выполнены (`gap_sanity_pass=1`, smoke 1×: A10 выполнен у всех 4 бросков).
**E0 разрешён** при условиях G1–G3. G4 не блокирует E0, но обязателен до E2.

## G1. Контроль спавна (только `Assets/Editor/SpikeBench/*`)
- В CSV каждого броска добавить `spawn_clearance_step0`: минимум `Collider2D.Distance` между каждым сегментом и коллайдерами головки и палочки сразу после `ResetToSpawn`, до первого шага физики.
- Бросок с `spawn_clearance_step0 < 0.01` получает `spawn_invalid=1` и не входит в статистику A10 и R. Число таких бросков — в `summary`.
- Если `spawn_invalid` > 2 % серии, E0 невалиден: стоп, дамп поз палочки и двух первых сегментов, вопрос в чат.
- Отдельно разобрать отрицательный `min_spawn_clearance_step0` из рапорта (C0): записать, в какой момент и при каком угле палочки он был замерен.

## G2. Живая проверка шарниров
- В `Ribbon.ValidateHingeAnchors` порог 0.001 и `LogError` оставить только для вызовов после `Build` и после `ResetToSpawn`.
- На шагах бенча слэк считать без `LogError`: максимум за бросок в CSV (`hinge_slack_max`), порог 0.02 (ADR-003-a4, A19).

## G3. Параметры E0
- Серия 100 тапов + 20 удержаний на 12×. Тапы 0.04…0.14 с, удержания 0.3…1.5 с, полная сетка перемешана по seed (как в поправке 2).
- Проверка 8 тапов + 2 удержания на 1×, `experiment_id` с суффиксом `_verify1x`; бенч сам сравнивает флаги A10 и разницу max_gap.
- Фазы: контакт / полёт / остановка. Гистограмма зазоров: бины 0.085 / 0.21 / 0.5 / 1.0, с разбивкой по фазам.
- `R_min_throw` (без первых 0.1 с, по числу шагов), максимум скорости сегмента, NaN.
- Вердикт A10 по полям первого события (C1), не по сырому максимуму.
- Конфиг и код рантайма не менять. Логика та же, что в `FixedUpdate`.

## G4. До E2 (не блокирует E0)
- B6 `Run Rest Probe` и B7 (колонки `fixed_steps`, `r_rest`, `slide_time`), если не сделаны. Статус записать в рапорт.
- Низкий приоритет (C7): в `RibbonMesh.Fill` брать концевые сечения из `transform`, а не из `Rigidbody2D.position/rotation`, чтобы все позы шли из одного источника. Метрика смещения: расстояние между точками сечений меша и мировыми точками шарниров (`GetRelativePoint`) на остановившейся ленте (`|v| < 0.05`). Старый порог 0.05 по центрам — справочный.
